# Multimodal PET/MRI classification of PD and MSA-P

Research software for differentiating Parkinson's disease (PD) from the parkinsonian subtype of
multiple system atrophy (MSA-P) using fused PET/MRI images, a shared Vision Transformer (ViT),
multi-slice voting (MSV), and Grad-CAM.

For each subject, the axial slice with the largest segmented striatal ROI is selected as the
center. The two neighboring slices on either side form a five-slice window with relative offsets
`[-2, -1, 0, 1, 2]`. One ViT is trained per cross-validation fold on all selected slices from the
training subjects. The same checkpoint produces the five validation probabilities for each
held-out subject, which are aggregated at subject level.

MSV is a decision-level aggregation method. ViT self-attention and Grad-CAM are separate
mechanisms.

## Features

- subject-level stratified four-fold cross-validation with leakage checks;
- dynamic center-slice selection from a three-dimensional ROI mask;
- one shared 384-pixel ViT classifier per fold;
- optional training augmentation, weighted sampling, and class-weighted cross-entropy;
- weighted MSV with relative-position weights `[0.10, 0.20, 0.40, 0.20, 0.10]`;
- patient-level metrics and bootstrap confidence intervals;
- Grad-CAM export for fused RGB slices;
- a separate four-fold nnU-Net v2 segmentation workflow.

The default class encoding is `0 = MSA-P` and `1 = PD`. With `positive_label = 1`, sensitivity is
PD recall and specificity is the true-negative rate for MSA-P.

## Installation

Python 3.10 or 3.11 is recommended. Install the PyTorch build appropriate for the local CPU or
CUDA environment, then install the project:

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
# Install torch and torchvision using https://pytorch.org/get-started/locally/
python -m pip install -r requirements.txt
```

Optional dependencies:

```bash
python -m pip install -r requirements/explainability.txt
python -m pip install -r requirements/dev.txt
```

## Classification data

The classifier reads pre-fused three-channel RGB PNG files. It does not read raw MRI/PET volumes
or infer the channel-to-modality mapping. The mapping used to create each RGB combination should
be recorded with the experiment.

Input volumes are expected on the MNI152 standard-space grid after SPM-based registration and
Neuromorphometrics atlas label transformation.

The manifest contains one row per subject and selected slice:

```csv
subject_id,label,center_slice_index,slice_offset,slice_index,fused_path
SYNTHETIC_001,1,18,-2,16,synthetic/SYNTHETIC_001/slice_016.png
SYNTHETIC_001,1,18,-1,17,synthetic/SYNTHETIC_001/slice_017.png
SYNTHETIC_001,1,18,0,18,synthetic/SYNTHETIC_001/slice_018.png
```

Each subject must have exactly one row for every configured offset, and `slice_index` must equal
`center_slice_index + slice_offset`. See [data/README.md](data/README.md) for the complete schema
and data-safety rules.

## Classification workflow

Edit [configs/classification.toml](configs/classification.toml) to point to the local manifest and
data root. Relative paths are resolved from the configuration file.

Audit the manifest before training:

```bash
pdmsa-audit-manifest --config configs/classification.toml
pdmsa-audit-manifest --config configs/classification.toml --check-files
```
Fold assignments

The reported experiments used prespecified patient-level four-fold assignments that were created before model training and reused throughout the corresponding evaluation.

The training code reads fold assignments from the file specified by splits.assignments_file. The exact subject-level assignments used in the clinical study are not included in the public repository.

For users who do not have prespecified assignments, the repository additionally provides a deterministic split-generation utility for retraining or methodological evaluation:

pdmsa-make-splits --config configs/classification.toml

Splits generated by this utility are compatible with the released workflow but should not be interpreted as the exact historical fold assignments used to obtain the manuscript-reported numerical results.

Train the shared ViT for folds 0 through 3:

```bash
pdmsa-train-fold --config configs/classification.toml --fold 0
pdmsa-train-fold --config configs/classification.toml --fold 1
pdmsa-train-fold --config configs/classification.toml --fold 2
pdmsa-train-fold --config configs/classification.toml --fold 3
```

Each fold writes one `best_model_weights.pth` checkpoint plus slice-level and subject-level
validation outputs. Compute pooled out-of-fold metrics directly from the four held-out files:

```bash
pdmsa-evaluate-oof --input \
  outputs/classification/fold_0/validation_slice_predictions.csv \
  outputs/classification/fold_1/validation_slice_predictions.csv \
  outputs/classification/fold_2/validation_slice_predictions.csv \
  outputs/classification/fold_3/validation_slice_predictions.csv \
  --output-dir outputs/oof_evaluation \
  --method weighted_soft --weights 0.10 0.20 0.40 0.20 0.10 \
  --positive-label 1
```

The weights are ordered by relative slice offset, not by absolute slice number.

## Grad-CAM

Generate a heatmap and overlay for one fused slice using the matching fold checkpoint:

```bash
pdmsa-gradcam --config configs/classification.toml \
  --checkpoint outputs/classification/fold_0/best_model_weights.pth \
  --input /path/to/fused_slice.png \
  --output-dir outputs/gradcam/example \
  --target-class 1 --target-layer 8
```

The output records class probabilities, target class and layer, model settings, and the
checkpoint checksum. Grad-CAM is a class-activation visualization; it is not an MSV attention
score or a slice-selection probability.

## nnU-Net segmentation

Segmentation is an independent preprocessing workflow. The repository provides deterministic
four-fold split generation and guarded wrappers around the official nnU-Net v2 commands. Setup,
training, and prediction instructions are in [docs/SEGMENTATION.md](docs/SEGMENTATION.md).

## Data safety and intended use

No clinical images, manual segmentations, real subject identifiers, fold assignments, model
weights, or server paths are distributed in this repository. Use pseudonymous subject keys and
keep all private data and generated artifacts outside the Git checkout.

This software is intended for research use only. It is not a medical device and must not be used
as a stand-alone diagnostic system.
